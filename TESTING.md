## Как провести реальные испытания

Выполните ConnectionCheck, затем IntegrationChecks для каждого файла подключения.
IntegrationChecks проверяет 16 условий и очищает временные данные в finally.
Он не заменяет ручные проверки интерфейса и административных операций.

| № | Сценарий | Ожидаемый результат |
|---:|---|---|
| 1 | Неверный пароль СУБД / недоступный сервер | Понятная ошибка, вход не открывается |
| 2 | Старая схема без составного ключа получателя | Сообщение о необходимой миграции |
| 3 | Неверный пароль приложения | Вход отклонён |
| 4 | Регистрация и повторный логин с другим регистром | Первая успешна, дубликат запрещён |
| 5 | Создать личный список, перезапустить и войти | Список сохранён |
| 6 | Два владельца создают получателя с локальным номером 1 | Оба профиля допустимы, данные разделены |
| 7 | Создать получателя с двумя интересами, изменить один | После повторного открытия сохранён точный набор |
| 8 | Ошибка назначения несуществующего интереса через IntegrationChecks | Откат всего изменения профиля |
| 9 | Удалить получателя с назначенным списком | Отказ БД, исходные записи сохранены |
| 10 | Желание: 100.25, отметка покупки, отмена | Сумма и статус сохранены, итог пересчитан |
| 11 | Цена -1, NaN, 1.001, пустое название | Отказ валидации до записи |
| 12 | Фильтр/поиск желаний | Отображение меняется, общий итог списка не искажается |
| 13 | Подбор для Мама/5000/ANY на исходных восьми идеях | Идеи 7 и 5, в этом порядке |
| 14 | Добавить идею в список, затем изменить цену идеи | Существующее желание сохраняет собственную цену |
| 15 | Войти обычным пользователем | Нет административных вкладок/операций |
| 16 | Администратор: создать идею с интересами, отключить | Сохранено; отключённая идея не участвует в подборе |
| 17 | Администратор: удалить используемый интерес | Отказ БД |
| 18 | Перенести проект и data/images на другую ОС | Изображения доступны; отсутствующие заменены заглушкой |
| 19 | Переключить файл PostgreSQL → SQL Server | Меняется подключение без пересборки |
| 20 | Импортировать полный каталог два раза последовательно | Все исходные варианты доступны, второй запуск не размножает точные варианты |

Результаты конкретного сервера/ОС заносить отдельно: дата, версия ОС/JDK/СУБД,
сценарий, ожидаемое и фактическое поведение, подтверждающий снимок экрана.
Не отмечать непроверенные сценарии как выполненные в итоговом отчёте.

# WishlistApp — Java 8 + JavaFX + JDBC

Версия приложения для шестого этапа учебного проекта. Данные хранятся в PostgreSQL
или SQL Server, подключение выбирается внешним файлом. ORM и фреймворков доступа к
данным нет. Восемь таблиц соответствуют исправленной модели с составным ключом
получателя (owner_id,recipient_id). Описание зависимостей: database/NORMALIZATION.md.

Исходный архив пользователя остаётся отдельной предыдущей версией. Здесь сохранены
JavaFX, карточки желаний, покупка/отмена, стоимость и подбор подарков. Интерфейс и
сервисы переработаны для нескольких списков, сохранённых получателей и JDBC;
старые FXML-контроллеры с демонстрационным ArrayList не используются.

## Быстрый запуск на Windows

1. Распакуйте архив в отдельную папку целиком. Не запускайте JAR прямо из ZIP.
2. Нужен JDK 8 с JavaFX 8: ваш прежний JDK, если он уже запускал исходный проект,
   либо Liberica JDK 8 Full. JDK, которым запускается Data Modeler, выбирать не нужно.
   JAVA_HOME для командных файлов должен указывать на JDK 8, либо java должен
   находиться в PATH. Maven и интернет для готовой сборки не требуются.
3. В папке config сделайте копию postgresql.example.properties под именем db.properties.
   При включённых расширениях имя должно быть db.properties, без добавленного .txt.
4. Отредактируйте db.properties обычным текстовым редактором:
   db.type=postgresql
   db.url=jdbc:postgresql://localhost:5432/postgres
   db.user=ИМЯ_ПОЛЬЗОВАТЕЛЯ_POSTGRESQL
   db.password=ПАРОЛЬ_POSTGRESQL
   db.schema=wishlistApp
   Пароль — пароль подключения СУБД из DBeaver, а не DemoPass123!.
5. Для нового развёртывания выполните 01_schema.sql, 02_seed.sql из папки database/PostgreSQL или database/SQLServer в зависимости от выбранной СУБД. Скрипт 01_schema.sql сразу создаёт структуру, соответствующую НФБК. 
6. Запустите run.bat. Выберите config/db.properties и нажмите «Подключиться».
7. Войдите как ivan / DemoPass123! (обычный пользователь) или admin / DemoPass123!
   (администратор), если использовали демонстрационное заполнение.

В PowerShell можно указать JDK только для текущего окна:
```powershell
$env:JAVA_HOME = 'C:\ПУТЬ_К_ВАШЕМУ_JDK8'
.\run.bat
```
Подставьте реальный путь; угловых скобок и bin в конце быть не должно.
Если готовая сборка удалена или исходники изменены, сначала выполните build.bat.
Все зависимости уже находятся в lib/. Готовый JAR — target/wishlist-app-2.0.0.jar,
а его зависимости — target/lib/. Эти файлы нужно переносить вместе.

## Подключение к SQL Server

Сделайте копию config/sqlserver.example.properties и заполните:
```properties
db.type=sqlserver
db.url=jdbc:sqlserver://localhost:1433;databaseName=WishlistApp;encrypt=true;trustServerCertificate=true
db.user=ЛОГИН_SQL_SERVER
db.password=ПАРОЛЬ_SQL_SERVER
db.schema=wishlistApp
```
Порт, сервер и имя базы замените своими. Пример использует SQL Server authentication.
Встроенная Windows authentication через DLL здесь не настраивается. Для локального
учебного сервера пример допускает его самоподписанный сертификат.
В окне подключения выберите этот файл. Пересборка приложения не нужна.

Файлы Properties читаются в UTF-8. Обратный слеш в значении экранируется вторым
слешем по правилам Java Properties; проще использовать имя сервера и TCP-порт.
Файл config/db.properties исключён из Git. В архиве нет действующих паролей СУБД.

## Открытие в IntelliJ IDEA

1. File → Open → выберите папку проекта или pom.xml.
2. File → Project Structure → Project SDK: ваш JDK 1.8 с JavaFX.
3. При импорте Maven драйверы подтянутся из pom.xml. Если Maven недоступен,
   добавьте оба JAR из lib через Project Structure → Libraries → + → Java.
4. Откройте src/main/java/wishlistapp/Launcher.java и запустите main.
5. Working directory конфигурации запуска — корень этой папки проекта.

В Eclipse можно импортировать Existing Maven Projects и выбрать JDK 8.
Maven — только инструмент сборки; приложение не использует Spring/Hibernate.
Сборка без Maven проверена через build.sh на настоящем JDK 8.

## Ubuntu

Установите/выберите JDK 8 Full с JavaFX и настройте JAVA_HOME. Затем из папки проекта:
```sh
sh build.sh
sh run.sh
```
Для GUI требуется графическая сессия и системные библиотеки JavaFX/GTK. Полноценная
проверка на пользовательских Windows и Ubuntu ещё не выполнена; команды предоставлены
для следующего этапа испытаний. Встроенные драйверы работают с обеими ОС.

## Интерфейс

- Мои списки: создание, изменение назначения, удаление с подтверждением.
- Желания: добавление/редактирование, изображение, удаление, покупка и отмена,
  поиск по названию и фильтр состояния. Итоговая стоимость считается по всем
  неприобретённым позициям выбранного списка независимо от фильтра.
- Получатели: имя, возраст, несколько интересов (Ctrl + щелчок в форме).
  Удаление получателя со списками блокируется БД.
- Каталог: просмотр и добавление идеи в выбранный собственный список.
- Подбор: сохранённый получатель, бюджет, повод. Только активные идеи в пределах
  возраста и максимальной цены. При наличии интересов обязательно хотя бы одно
  совпадение; сортировка по числу совпадений, цене и идентификатору.
- Администратор: создание/изменение идей, диапазоны цен и возраста, интересы,
  активация/деактивация; отдельная вкладка управления справочником интересов.
- Саморегистрация создаёт только USER. Администратор не просматривает чужие личные
  списки через интерфейс. Права проверяются также в Repository.

Переключение вкладки/выход не уничтожает записи: после повторного входа они читаются
из БД. Все запросы выполняются в фоновом потоке JavaFX. Сообщение об ошибке не
означает успешное сохранение. Изменения профиля и назначений интересов атомарны.

## Исходные 55 идей

Приложение сразу работает с восемью демонстрационными идеями в вашей БД.
Для переноса полного каталога предусмотрены НЕОБЯЗАТЕЛЬНЫЕ скрипты:

- database/06_import_original_catalog_postgresql.sql
- database/06_import_original_catalog_sqlserver.sql

Они переносят все 55 исходных записей из GiftIdeaGenerator. «Цветы» имели два повода,
поэтому представлены двумя вариантами. Всего получается 56 импортируемых вариантов
и 64 различных интереса. Имеющиеся записи не удаляются и не перезаписываются:
пропускаются только точные варианты по названию, описанию, ценам, возрасту и поводу.
Таким образом, демонстрационная идея и исходная идея с другим диапазоном цен могут
появиться как две отдельные строки. Это допустимо по нашей модели.
Импорт повторяемый при последовательном выполнении. Одновременно из двух окон
его запускать не следует. Запускайте после базовых проверок БД: результаты подбора
после импорта станут другими. Нажмите «Обновить» в приложении после выполнения.

Исходные данные сохранены также в database/original_catalog.json для сверки.
Отсутствовавшие в оригинальном архиве изображения подарков заменяются заглушкой.
Эмодзи не перенесены в отдельный столбец; возрастные группы переведены в диапазоны.

## Изображения

Выбранный файл копируется в data/images, в БД хранится относительный путь. Если
переносите базу вместе с фотографиями на другой ПК, переносите и папку data/images
в тот же корень проекта. При недоступном изображении показывается заглушка.
При неудачной записи в БД уже скопированный файл может остаться неиспользуемым;
автоматическое удаление таких файлов в этой версии не предусмотрено.

## Структура программы

| Класс | Назначение |
|---|---|
| Launcher, MainApp | Запуск JavaFX и обработчики интерфейса |
| Models | Объекты пользователя, получателя, списка, желания, идеи и интереса |
| Repository | JDBC-запросы, транзакции, проверка владельца и административных прав |
| Database | Соединения, тайм-ауты, проверка схемы |
| SqlDialect и две реализации | Отличия SQL PostgreSQL/SQL Server |
| Config | Внешний файл Properties |
| PasswordHasher | PBKDF2WithHmacSHA256, случайная соль, сравнение хешей |
| Validation, Images | Валидация значений и переносимые изображения |
| ConnectionCheck | Консольная диагностика подключения без изменений данных |

Пользовательские значения передаются через PreparedStatement. Для выдачи следующего
локального номера получателя Repository блокирует строку владельца, получает MAX+1
в его пределах, вставляет профиль и интересы и фиксирует одну транзакцию.
Свойства пароля читаются из БД (включая число итераций); формат совместим с seed.sql.
Новых внешних таблиц, дополнительных БД или серверного HTTP-приложения не требуется.

## Проверки

После build.bat в Windows:
```bat
java -cp "target/classes;target/test-classes;lib/*" wishlistapp.CoreChecks
java -cp "target/classes;lib/*" wishlistapp.ConnectionCheck config/db.properties
java -cp "target/classes;target/test-classes;lib/*" wishlistapp.IntegrationChecks config/db.properties
```
В Ubuntu замените ; на : в classpath.
Используйте java выбранного JDK 8 (при необходимости полный путь к java.exe).

CoreChecks: 20 проверок без БД — деньги, возраст, пустые значения, SQL-хеш пароля,
неверный пароль, уникальность соли, конфигурация, синтаксис схемы и загрузка драйверов.
ConnectionCheck: подключение и наличие составного ключа, без изменений данных.
IntegrationChecks: реальные JDBC-операции на выбранном сервере; создаёт две временные
учётные записи it_..., получателей, списки и желания. Проверяет вход, изоляцию владельцев,
составные ключи, откат ошибок назначения интересов и каскадное удаление.
Созданные тестом данные удаляются в finally; пропуски автоматических ID допустимы.
При аварийном завершении процесса очистка может не выполниться; удалите только записи
созданных тестовых пользователей в порядке wishlist → recipient → app_user.

Результаты подготовки: TESTING.md. Проверки на ваших двух СУБД, обеих ОС и независимое
развёртывание одногруппником пока НЕ подтверждены. Исходные SQL-скрипты сохранены
в database/PostgreSQL и database/SQLServer для развёртывания с нуля или миграции.
